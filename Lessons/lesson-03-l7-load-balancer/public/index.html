What this teaches

Distribute traffic across multiple servers.

The next improvement is to add a load balancer.

A load balancer sits in front of multiple application servers and distributes incoming traffic between them.

It can operate at different layers:

  • Layer 4 – Transport Layer: Uses transport-level information such as IP addresses, ports, and protocol. It sees less of the request, which allows it to make fast, efficient routing decisions.
  • Layer 7 – Application Layer: Understands application-level information such as HTTP methods, hostnames, headers, URLs, paths, and cookies. It can make more intelligent, content-aware routing decisions, with some additional processing overhead.

A Layer 7 load balancer behaves much like a specialized reverse proxy.

Some key advantages are:

  • Load distribution: Prevents a single server from handling all requests.
  • High availability: If one server goes down, traffic can be routed to healthy servers.
  • Horizontal scaling: More servers can be added as traffic increases.
  • Health checks: Unhealthy servers can automatically be removed from rotation.
  • Better resource utilization: Traffic can be distributed using different load-balancing strategies.

The flow now becomes:

Client→Load Balancer→Multiple Application Servers

In our setup

This is a Layer 7 load balancer. It can inspect the HTTP request, including the /api/products path, before selecting an upstream server.

We use Nginx as the load balancer and run three Catalog Service instances. Nginx sends requests to them in round-robin order and returns every response through one stable client-facing address.
