What this teaches

Distribute traffic across multiple servers.

A load balancer sits in front of multiple application servers and distributes incoming traffic between them.

L4

Transport Layer

Uses IP addresses, ports, and transport protocols. It sees less of the request, allowing simple and fast routing decisions.

L7

Application Layer

Understands HTTP methods, paths, headers, hostnames, and cookies. It can make content-aware routing decisions with additional processing.

A Load balancer behaves much like a specialized reverse proxy. In this lesson, Nginx can see the /api/products path before selecting a Catalog replica.

  • Round robinRequests are assigned to healthy servers in a repeating sequence, giving each one a turn.
  • Horizontal scalingCapacity is increased by adding more server instances rather than making one server larger.
  • Health checkA periodic test determines whether a server is available to receive traffic.
  • FailoverTraffic is sent to another healthy server when the preferred server cannot answer.

Same technology, different purpose

Nginx now balances rather than caches.

Lesson 2 forwarded to one application server and demonstrated response caching. Lesson 3 runs three Catalog Service instances and uses Nginx round robin to distribute every request. There is no response cache here.

What this gives us

  • Traffic distributed across replicas
  • Horizontal scaling
  • Better resource utilization
  • Service availability when one replica fails
  • One stable address for the Catalog Service
  • Selection of a healthy application instance

What still remains

  • The Load Balancer is now a Single Point of Failure (SPOF)
  • It handles only the Catalog Service
  • The client still needs different addresses for User, Order, and other services
  • Authentication and rate limiting remain distributed concerns

The next design pressure

How does the client reach different services?

The Load Balancer selects an instance of one service, but a growing application exposes many different services and APIs.
